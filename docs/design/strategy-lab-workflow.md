# 策略实验室：从想法到可验证实验

## 产品选择

采用「对话澄清 + 结构化规则 + 可审查代码」的混合工作流。新手不需要先学会编程，也不需要理解一屏参数；专业用户仍能接管代码、查看差异和恢复版本。

单纯参数面板只能覆盖有限策略；纯聊天直接写代码则会隐藏歧义和执行风险。共同的中间层应当是用户能确认、系统能校验的策略规则，而非一条巨大 prompt。

## 本次已实现

- 默认规则构建：研究备注、50/100/200 日均线预设、标的、仓位、可读的买卖及执行约定。
- 均线天数与成本逐层展开；填写项有标签、范围和解释。
- 应用规则以确定性编译器生成完整策略代码，同步配置、仓位及成本。明确确认替换当前代码，自定义逻辑不合并。研究备注不被当作指令。
- 参数草稿独立于当前代码；草稿未应用时阻止实验，支持撤销草稿。运行时检查日期和资金，再执行语法检查、保存版本、提交真实回测。
- 桌面右侧实验设置与运行入口；小屏顺序排列。专业模式展开研究配置，给代码和历史对比更大空间。
- 研究助手与验证放在可关闭、支持键盘的对话面板，移动端同样可达。
- 回测结果沿用真实 RunDock 和回测详情页，不生成虚构收益或验证结果。

当前生成器仅支持单标的均线趋势；等权模板与自定义代码仍在专业模式。已有策略的配置可能与代码不一致，规则卡片明确标注为待应用预览，不宣称反向解析任意 Python。研究助手当前仅作事实解释，不生成代码。

## 后续模型生成：建议接口与系统设计（尚未实现）

1. **意图澄清**：输入用户想法、最近确认的规则；识别标的、信号、仓位、退出、成交时点、成本。缺失的关键交易定义列为待确认问题。上传文件和行情文本只作为资料，不能改变系统权限。
2. **规则草案**：服务端输出有版本的 JSON schema，包含 universe、signal、position_sizing、risk、execution、assumptions、unsupported。每个假设区分用户指定与模型补全；不静默补上杠杆、做空或风险限制。
3. **能力校验**：检查可用数据、字段频率、取值范围、支持的策略算子。先支持明确的策略语法树，再考虑任意代码；不支持的语义显式返回。
4. **代码编译与检查**：受支持规则尽可能由确定性编译器实现。其他模型代码作为候选，进行语法、依赖、未来数据引用、信号/成交时点和沙箱检查，不能保证仅靠静态检查消除所有错误。
5. **差异确认**：界面首先展示「原规则 → 新规则」及新增假设，专业用户展开代码差异。以源版本 ID 和代码哈希检查过期草稿，只有确认后才能创建版本。
6. **实验执行**：版本与参数锁定，记录数据快照、费用和试验次数；使用现有回测队列。AI 不更改验证结果和研究状态。
7. **结果解读**：只读取真实结果，比较基准与上一个版本，引用指标及时间范围。把观察与解释分开，不能把回测收益承诺为未来收益。

建议拆分服务端职责为意图澄清、规则 schema、策略编译、检查、差异与版本、执行、结果解释。提示词模板分别约束各阶段的输入输出，而不是混合进一个无限制的聊天接口。

模型写策略需要单独设计数据授权边界。现有研究助手承诺不发送源码、参数与行情，不能复用该接口悄悄扩展出站数据。未配置模型时保留规则构建，并明确显示模型不可用。

## 验收重点

修改仓位必须影响生成代码；零滑点不能回退为 5 bps；不合法规则和日期不能运行；草稿必须先应用或撤销；自定义代码不被默默覆盖；版本恢复可用；助手关闭与 Escape 可用；375px 宽度无页面横向溢出。
