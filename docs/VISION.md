# Axiom Street 产品愿景

> 这份文档定义 Axiom Street 是什么、为谁而做、以及**明确不做什么**。
> 当路线图与愿景冲突时，愿景优先。当功能需求与「不做什么」冲突时，拒绝需求。

---

## 一句话

**Axiom Street 是一个让你难以自欺的量化研究环境。**

它不追求成为最快的回测器，而是成为最诚实的那个。

---

## 1. 为什么存在

量化研究真正的失败模式，不是「找不到策略」，而是**「找到了一个不存在的策略，并且信了它」**。

一个下午，任何有编程能力的人都能在 SPY 上搜出一条 Sharpe 2.5 的净值曲线。它是假的。它假的原因通常不是数据错了，也不是代码有 bug——而是**你在同一份数据上试了 400 次，然后挑了最好的那一次**。挑选行为本身就是偏差来源，而回测报告不会告诉你这件事。

这个问题有个残酷的性质：**它在样本内完全不可见**。所有的图表都很漂亮，所有的指标都很健康，直到你投入真金白银。

市面上的产品分为两类，都没有解决它：

| 类别 | 代表 | 问题 |
|------|------|------|
| 零售量化平台 | Composer、Tradetron、各类信号订阅 | 在优化「更快做出更漂亮的回测」——也就是在优化通往破产的路径 |
| 机构级工具 | Bloomberg PORT、FactSet、Axioma | 昂贵、非研究工作流原生，且假设你已经有一支懂纪律的 quant 团队 |
| 开源库 | backtrader、vectorbt、zipline | 是库不是产品，纪律完全依赖使用者的自觉 |

QuantConnect / LEAN 提供了优秀的引擎——所以我们直接用它，不重复造。**但引擎不等于研究纪律。** LEAN 会忠实地执行你的过拟合策略，并给你一份漂亮的报告。

**空白就在这里：没有一个产品把「统计有效性」当作核心功能，而不是可选的附加报告。**

Axiom Street 填这个空白。

## 2. 核心信念

这六条是产品的宪法。任何实现决策都可以回溯到它们。

### 信念一：诚实优于速度

一个错误的数字比没有数字更糟。宁可让回测失败并明确报错，也不输出一个"大概对"的结果。

**具体含义**：
- 数据源不支持分红调整 → 回测直接失败，而不是静默用未调整价格
- 数据质量校验不通过 → 阻塞回测，而不是加个小字警告
- 手续费无法解析 → 抛错，而不是记为 0
- 空态用诚实文案，永远不用 mock 数据冒充回测结果

### 信念二：纪律由系统承担，而不是靠用户自律

用户在兴奋地找到一条漂亮曲线时，是不会主动去做样本外检验的。指望自律是产品设计的失败。

**具体含义**：
- 未通过 walk-forward 的策略，**在系统层面无法**被标记为已验证
- 试验次数被自动记录，用户无法"忘记"自己试了多少次
- Deflated Sharpe 显示在 tearsheet 最顶部，比原始 Sharpe 更醒目
- 过拟合概率超过阈值时，界面主动给出红色警示

**走捷径应该是困难的。这是功能，不是障碍。**

### 信念三：可复现是不可协商的

三个月后重跑同一个回测，必须得到逐点相同的结果。做不到这一点，之前所有的研究结论都失去意义。

**具体含义**：
- 数据快照不可变、内容寻址，摄取新数据不覆盖旧快照
- 每个回测记录其数据快照 ID 与引擎版本
- Golden backtest 是引擎正确性的哨兵，容差不允许为了通过测试而放宽

### 信念四：AI 是研究助手，不是策略工厂

AI 在量化领域最大的风险，是它能以人类无法企及的速度批量生产**看起来很好的过拟合策略**。

**具体含义**：
- 验证基建必须先于 AI 能力上线（这是路线图重排的原因）
- AI 的每次试验都计入多重检验惩罚，不存在"AI 快速通道"
- AI 不能修改风控限额，不能改变策略验证状态——代码层面隔离
- AI 最有价值的用法之一是**劝用户停下来**："你已在此数据上试了 47 次，继续搜索的统计惩罚已经很重"

### 信念五：风控独立于一切

风控引擎不属于策略，不属于 AI，不属于任何可被绕过的路径。链路永远是 `Strategy → Risk → Execution → Broker`。

### 信念六：界面的克制本身就是可信度

一个用紫色渐变、霓虹光效和机器人图标包装的量化产品，在传递一个信号：它在卖梦想而不是卖工具。

**具体含义**：白底、单一主色 `#1677FF`、克制的红绿、`tabular-nums` 的财务数字。数据本身就是主角，不需要装饰。详见 `design-system/axiom-street/MASTER.md`。

## 3. 为谁而做

### 主要用户

**有编程能力的严肃个人研究者**——管理自己的资金或少量外部资金，能读懂 Sharpe 与 drawdown 的区别，愿意为"知道自己的策略是假的"付费。

他们现在的处境：用 Jupyter + backtrader 手工搭研究流程，纪律全靠自觉，每个人都在重复造同样的验证轮子，而且大部分人造得不对。

### 次要用户

**小型基金 / 家族办公室的 1–3 人研究团队**——需要机构级纪律，但买不起也不需要 Bloomberg 全套。

### 明确不服务

- **想买信号的人**——这是订阅服务，不是研究产品
- **想要 no-code 一键生成策略的人**——no-code 在量化领域等价于"不理解自己在做什么"，我们无法保护这类用户
- **高频 / 做市 / 微观结构研究者**——完全不同的基础设施问题（tick 级数据、纳秒延迟、交易所直连），不在射程内

拒绝服务这三类人，是产品聚焦的前提。

## 4. 明确不做什么

反目标和目标一样重要。以下每一条都是有意识的放弃：

| 不做 | 原因 |
|------|------|
| **策略市场 / 社交排行榜** | 排行榜是过拟合的激励机器。「展示你最好的回测」与「找到真实的 edge」是对立的目标 |
| **信号订阅 / 跟单** | 变成卖预测而不是卖研究能力，与信念二直接冲突 |
| **高频与微观结构** | 不同的基础设施与不同的用户，会撕裂产品定位 |
| **加密永续合约的高杠杆赌场** | 现货与主流衍生品可以支持；为赌博优化的功能不做 |
| **回测速度的极限优化** | 速度重要但不是核心竞争力。够快就行（Phase 4 的目标是秒级迭代，不是微秒级） |
| **自研回测引擎** | LEAN 已经足够好且经过实战检验。造引擎是虚荣工程，不是价值创造 |
| **无验证支撑的 AI 对话界面** | 没有真实能力支撑的聊天框是演示品，不是产品 |
| **多语言策略支持（C#/R/Julia）** | Python 覆盖 95% 的用户，其余的复杂度不值得 |

## 5. 成功是什么样子

### 场景一：过拟合被拦住

研究者花一周做出一个双均线策略，样本内 Sharpe 2.3。他点"验证"。

系统在 4 分钟后返回：**过拟合概率 71%**。Deflated Sharpe = 0.4（考虑到你在此数据上的 132 次试验）。参数响应曲面显示最优点是孤峰而非高原。盈亏平衡成本 3.2 bps——低于该标的的真实交易成本。

他没有亏钱。**这就是产品的全部价值。**

### 场景二：微弱但真实的 edge 被识别

同一个研究者跑 SPY 200DMA。系统返回：CAGR 1.3%，Sharpe 0.05，过拟合概率 12%。结论是"edge 微弱但不是过拟合产物，在高波动制度下有防御价值"。

**产品诚实地告诉他：这个策略很平庸，但它是真的。** 这比给他一个假的 Sharpe 2.5 有价值得多。

### 场景三：回测与实盘对得上

策略上实盘三个月后，系统展示回测预期与实盘实际的逐日偏差：累计 18 bps，主要来自开盘滑点。

**偏差可解释、可量化，因此整个研究体系值得信任。**

## 6. 北极星指标

大多数产品会选"回测运行次数"作为活跃度指标。**对我们这是有害的**——它奖励暴力搜索，与信念二直接冲突。

**我们的北极星：通过验证的策略，其实盘/样本外表现与回测预期的偏差分布。**

这个指标衡量的是产品的唯一承诺：**我们给你的数字是真的吗？**

它很难优化，因为它不能靠加功能提升，只能靠数据质量、成本建模、执行建模和验证严谨度的真实改进来收窄。这正是它适合做北极星的原因。

辅助指标：
- 被验证流水线拦下的策略比例（健康值应该很高——如果太低，说明验证不够严）
- 从想法到完成验证的时间（研究速度）
- 数据质量报告的问题发现数（数据可信度）

---

## 7. 与路线图的关系

愿景决定了阶段顺序，而不是相反：

- 信念一、三 → **Phase 1.5 可信性加固**（修正错误数字、不可变快照）
- 信念二 → **Phase 3 统计验证引擎必须先于 AI**
- 信念四 → **Phase 5 AI 受验证约束**
- 信念五 → **Phase 7 Live 之前风控必须实体化**
- 北极星 → **Phase 6/7 的回测–实盘对账是必做项，不是加分项**

完整施工计划见 `docs/ROADMAP.md`。
