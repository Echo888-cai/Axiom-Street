# 模拟盘与风控前端设计

## 目标

把已有的纸面订单、账户、持仓、对账 API 变成可操作的 `/paper` 页面，并为 `/risk` 提供只读、服务端计算的风险摘要。页面不计算成交、净值或风险结果，也不提供修改系统风控限制的入口。

## 范围

### 模拟盘页面

`/paper` 提供：

- 策略选择，仅展示可用于纸面执行的策略；
- 买入/卖出表单：标的、数量、模拟成交价、客户端订单号；
- 账户卡片：初始资金、现金；
- 当前持仓：数量、均价、标记价、已实现盈亏；
- 最近订单：排队、成交、拒绝和失败状态，以及服务端风险原因；
- 最近对账：MATCHED/DRIFT 状态和差异数量；
- 查询失败、空账户、空订单和空持仓的诚实状态。

下单调用现有 `POST /api/v1/paper/orders`，返回 `202 queued` 后刷新订单、持仓和对账查询。前端不乐观地增加现金、持仓或盈亏。

### 风控页面

新增只读 `GET /api/v1/risk/summary?strategy_id=<uuid>`。服务端读取最新策略版本的 `config.risk_limits`、纸面账户、持仓和最近对账，并返回：

- 策略状态；
- 风控配置及其是否有效；
- 账户现金与按持仓标记价计算的权益；
- gross/net exposure；
- 最近对账状态；
- 阻断原因列表。

摘要计算放入 `quant/risk` 纯函数并测试边界。API 只负责数据库读取和序列化。风险页面只读展示这些字段，不提供修改风险配置的控件。

## 边界与失败策略

- 缺少策略、账户或风控配置时显示明确的“未就绪”，不填充零值冒充健康状态；
- 非法或缺失 `risk_limits` 标记为无效，不能由前端绕过；
- 纸面订单仍由 Worker 和既有风控门执行；页面只提交请求和读取台账；
- Live 页面、Live Broker、外部凭证和真实订单发送保持不变；
- 单用户本地部署边界保持不变。

## 验收标准

1. `/paper` 可以从策略选择到提交真实 API 订单，并显示服务端返回的订单/持仓/对账状态。
2. `/risk` 显示服务端计算的风险摘要和阻断原因，不能修改风险限制。
3. 没有后端数据时所有页面均显示诚实空状态，不能出现模拟资金或模拟收益。
4. 纯风险摘要有边界测试；API、API 客户端和 React 页面均有失败先行测试。
5. `make test-all`、前端类型检查和生产构建通过。
