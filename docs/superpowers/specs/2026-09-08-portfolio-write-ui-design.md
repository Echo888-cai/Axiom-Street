# 组合写入工作流设计

## 目标

把 E8-1 已有的组合创建、策略权重配置和单期收益归因 API 接入 `/portfolios` 页面，使组合归因从只读展示变成可操作的服务端驱动工作流。

## 页面流程

### 创建组合

当组合列表为空或用户点击“新建组合”时，显示名称、基础货币和初始资金表单。提交调用 `POST /api/v1/portfolios`，成功后刷新组合列表并选中新组合。错误直接显示后端错误，不假装创建成功。

### 配置策略权重

选中组合后，显示已有生效区间配置，并提供策略、权重、生效日、可选失效日表单。提交调用 `POST /api/v1/portfolios/{id}/allocations`。页面显示当前配置权重总和；服务端仍负责策略存在性、日期冲突和字段校验。

### 提交收益归因

页面按指定 `as_of` 日期读取当前有效配置，为每个策略生成一行策略收益和基准收益输入。提交调用 `POST /api/v1/portfolios/{id}/attribution`，只提交收益输入，不提交权重。服务端从数据库读取权重并计算 Brinson 归因，避免浏览器篡改权重。

## 边界与失败策略

- 页面不计算归因结果；只展示服务端返回的快照；
- 没有策略、配置或组合时显示空状态，不生成虚拟数据；
- 权重总和不为 100% 时前端提示，但不能代替服务端校验；
- 同一日期重复提交由服务端返回冲突，页面保留已有快照；
- 输入错误、网络错误和后端 409/422 都显示可读错误；
- 不新增删除/覆盖接口，不破坏已有不可覆盖快照契约。

## 验收标准

1. 用户可以创建组合并在页面看到新组合。
2. 用户可以为组合添加策略权重和有效日期，并看到服务端返回的配置。
3. 用户可以为当前配置的每个策略提交策略收益和基准收益，并看到最新归因结果。
4. 请求体不包含由浏览器计算或覆盖的权重；服务端权重是唯一归因输入来源。
5. 表单失败、空状态和重复日期都有明确反馈；现有读展示不回归。
